# Design decisions

Settled 2026-10-22 by the maintainer. Answers the 4 open questions in `spec.md` §5.6, plus general constraints.

| # | Question | Decision | Why |
|---|---|---|---|
| 1 | Agent permissions | Default matches the original app: the agent self-approves (`bypassPermissions` for Claude, the equivalent flag for other CLIs), cwd = project folder. Settings has a switch `agent_permission_mode = auto | ask` (ask: Claude uses `acceptEdits`, other CLIs drop the self-approve flag). | Local single-user app; running without answering every command is the core experience. The switch lets users tighten it when needed. |
| 2 | Chrome for export | Use only the Chrome/Edge/Chromium already installed (found via standard paths + `OD_CHROME_PATH`). Never auto-download Chromium. Without one, PDF falls back to webview printing and screenshots fail with a clear "Chrome required" error. | No hidden outbound network; the owner's machine already has Chrome. |
| 3 | Brand-named design systems (revised 2026-10-25, owner) | Keep all 152 bundled design systems with their names, attribution and nested LICENSE files. The 90 named after a real company or product state it as `brand` in `manifest.json`; the app shows "Inspired by <Brand>'s public design language. Not affiliated with or endorsed by <Brand>. Trademarks belong to their owners." on their page in every UI language, and `NOTICE` and the README say the same. | The 2026-10-22 decision (ship as is) rested on "local app, not publicly released"; that no longer holds, since Contour ships as a public macOS beta. The brand names are what make the presets useful, so the owner chose a clear non-affiliation note over renaming or removing them. |
| 4 | Prompt set | Legacy set only (`apps/daemon/src/prompts/` of the original app), rewritten in Rust. No rollout/A-B. | Clear structure, all in one place. |
| 5 | Product name (2026-10-24, owner) | The app is **Contour** (was "Nét"): UI in every locale, window and menus, CLI help, bundle `Contour.app`, identifier `dev.contour.desktop`, data folder `contour` under the platform data dir. The first run moves an existing `open-design-rs` data folder to `contour` and leaves a symlink at the old path (Unix). Crates and binaries keep their `od-*` / `od` names, and env vars keep the `OD_` prefix. | A global name that reads the same in every language. Renaming 20 crates, the `od` binary and the `OD_*` variables would touch every import, script, MCP config and agent prompt for no user-visible gain, and would break installs that already call `od`. |
| 6 | `OD_NODE_BIN` and `media scaffold` for Motion (2026-11-01, Atlat brief beta.10) | Contour sets `OD_NODE_BIN` to the same native binary as `OD_BIN`, and `od` drops a first argument that names its own executable, so the content's `"$OD_NODE_BIN" "$OD_BIN" media …` runs as written on macOS, Windows and Linux. The desktop app, which is the `OD_BIN` of its runs, answers the CLI's client commands (`media`, `files`, `project`…) without opening a window. `od media scaffold` writes a composition with a plain seekable timeline (no GSAP bundled); `od media generate --model hyperframes-html` renders it with the installed Chrome and ffmpeg (#2), and a missing one is a clear error the skill tells the agent to report, never a pipeline of its own. | A shim keeps the 18 copied skill and prompt files (and later copies from the original) untouched, where rewriting them would fork the content. A wrapper script would need a separate file per platform (`.cmd` on Windows) next to the binary. The content contract test (`crates/od-cli/tests/content_contract.rs`) keeps content and host in step. |
| 7 | `unsafe_code` in `od-desktop` (2026-11-08, Atlat brief QA-064 follow-up) | The workspace forbids `unsafe_code`; `od-desktop` alone denies it (`apps/desktop/Cargo.toml` `[lints]`) and allows it only in `src/js_dialogs.rs`, which adds the JavaScript panel methods to wry's Objective-C UI delegate. Since the crate cannot use `[lints] workspace = true`, it copies the other workspace lints, and both places carry a comment to keep them in step. | `forbid` cannot be lifted by a local `allow`, and calling Objective-C needs `unsafe`. `deny` keeps every other file of the crate unsafe-free. |
| 8 | Version history of a deleted or replaced page (2026-11-15, Atlat brief histstate, QA-102) | A closed history (its page deleted in the app, or replaced outside it while renamed away) is hidden: the Versions panel lists only the page now at that name, and reading or restoring an entry of the closed history answers `VersionNotFound`. Every restore first keeps what the file holds in a version (`ensure_current_version`, as an edit does). A file that is not UTF-8 cannot be kept (a version holds text), so a restore over it is refused (`BadRequest`) rather than overwriting it (2026-11-15, histfollow). A restore or edit whose new version cannot be recorded puts the file back before reporting the error: the caller needs that version, so it cannot be only logged as other history updates after a write are. The original app instead lets a restore of a deleted history's entry reopen it (`preserveDeletedHistory`, `project-file-versions.ts`). | In Contour that branch could only run while another file already stood at the name (the panel answers 404 for a missing file), so it showed the old page's versions for the new one and overwrote the new file without a snapshot: the only copy was lost. Restoring a deleted page is not a flow Contour offers. |
| 9 | "Copy to Claude Code" only in the desktop app (2026-11-25, Atlat, PR #337 review) | A Personal skill is copied into `~/.claude/skills/<id>` (the agents' `HOME`) only by the desktop app's Tauri command `copy_skill_to_claude`, which calls `od_server::skill_export::copy_to_claude` in process. No HTTP route and no `od` command writes there; `GET /api/skills/:id/export?target=claude` only reads (where it would go, its source, what is there, the warnings, the `SKILL.md`, the files and their `hash`). The app always shows that content for review first, and the command takes its `hash`: a skill changed since (any file copied, not only `SKILL.md`) is refused (`changed`, "Skill changed since you opened this. Review it again.") and the new content is shown; the bytes compared are the bytes written (2026-11-25, Atlat, follow-up #337). A missing `description` is a warning, not a stop: Claude Code 2.1.332 still loads the skill and shows the first line of its body. The web app shows `command -v rsync >/dev/null && mkdir -p '<dest>' && rsync -r --exclude='.*' '<source>/' '<dest>/'` to run instead (with no `rsync` it stops before making a folder): like the app it skips links and hidden names, and a second run copies into the same folder (it also skips `.claude-plugin/` below the top, which the app copies). | An agent in a run reaches the daemon on loopback from outside its sandbox (the token guard lets loopback through, and `od` is on its PATH): a route or `od skill export` let it turn a skill of its own making into a global Claude Code skill loaded in every later session, with no click (reproduced in review: 201 under a Seatbelt profile that denies writes to `~/.claude`). It can still edit a Personal skill over loopback (`PUT /api/skills/<id>`) and wait for the user's click; the review and the hash make the click copy only what the user read. Tauri IPC is granted only to the daemon's origin in the app window; design frames are sandboxed without `allow-same-origin`, so a page an agent writes cannot call it. |

## General constraints
- **No login, no cloud, no telemetry, no outbound network** except calls to the agent/provider the user configures. E2e tests block every request outside loopback.
  - Exception (2026-10-28, owner): **Check for Updates** (Help menu, Settings ▸ About) calls the GitHub Releases API only when the user clicks it. It sends nothing but the request and its User-Agent, and never runs in the background. E2e tests check that start-up sends no request.
  - Exception (2026-11-04, owner): **Update now** in that dialog downloads the release it found (`latest.json` and the build, from GitHub Releases), installs it only when its minisign signature matches the updater key in `tauri.conf.json`, and restarts on Restart. Only that click downloads; nothing updates in the background.
- **Stack**: Cargo workspace, edition 2024, tokio, axum, rusqlite (bundled), Leptos CSR (UI), Tauri 2 (shell). Crate layout per `spec.md` §5.2.
- **Performance**: follow the target table in `spec.md` §5.5; each milestone has benches for the parts it touches.
- **Rust code** follows the `rust-skills` skill (`.claude/skills/rust-skills`).
- **16 GB dev machine**: `.cargo/config.toml` caps `jobs = 4`; heavy tests run serially.
- **Content** (skills, design-templates, design-systems, craft…) is copied from the original app per the table in `spec.md` §3.7, keeping every nested LICENSE; prompt templates with unclear licenses and unlicensed fonts are excluded.
- **Repository**: `quangphung218/contour-design` on GitHub. Work merges into `main` after review.
