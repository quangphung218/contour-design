API equivalent where there is one. Every feature here is scored in
[parity.md](parity.md), which has the evidence (code and e2e steps) for each
row. Commands assume a daemon on the default port; from a source checkout
replace `od` with `cargo run -q -p od-cli --bin od --`.

## Home and projects

**Home** is where a design starts. Type a brief and press Enter: Contour
creates the project and sends the first turn to the agent.

- **Output type** chips: Prototype, Website clone, Wireframe, Mobile app,
  Slide deck, Document, Image, Video, Audio.
- **Design system** and **template** pickers, plus a *Start from a
  template* gallery.
- **"+" menu** and **@ search** to attach files, plugins, skills and MCP
  servers as context.
- **Working directory** picker to point a project at an existing folder.
- **Recent projects**, *Recommended for you*, the message center, and the
  language and theme switchers.

**Projects** (left rail) lists every project as a grid, list or kanban board
by run status. Rename, duplicate, delete (also several at once), filter and
sort; **Cmd/Ctrl+K** searches projects and conversations.

- **Open a folder as a project**: Project ▸ Open Folder… (Cmd+O) in the
  desktop app, or the folder button on Projects.
- **Import ZIP**: a Claude Design export becomes a project; its entry HTML
  file is detected.
- **Project instructions**: extra rules sent with every turn of that project.

```bash
od project create --name "Landing"        # prints "<project-id><TAB>Landing"
od project list
```

## Studio: chat

The left pane of a project talks to the agent.

- Streaming text, thinking, tool rows and Markdown; **Stop** cancels the run
  and every process it started.
- Several **conversations** per project; **fork** from any message.
- **Session modes** Ask, Plan and Design; a todo list with a *step N/M* pill.
- **Composer**: attach or paste files, reference another project or local
  code, pick a design system, `@` mentions, slash commands (`/mcp`,
  `/search`), switch agent or model inline, queue messages and steer a
  running turn.
- **Question forms** and **GenUI** surfaces when the agent needs an answer;
  remembered answers are reused.
- **Design Jury**: an optional critique pass after a run (`OD_CRITIQUE_ENABLED`
  turns it on by default), with interrupt and replay.
- **Project memory**: "Remember that…" saves facts the agent sees next time;
  a toast confirms each save.
- After a run, a warning appears when the agent produced no deliverable.

```bash
od run start --project <project-id> --agent claude --message "Landing page for a tea shop" --watch
od run watch <run-id>      # NDJSON events, exits 0 when the run succeeds
od run cancel <run-id>
```

## Studio: preview and editing

The right pane shows the design in a sandboxed iframe that reloads when a
file changes.

- **Preview / Code** toggle with syntax highlighting; device sizes Desktop,
  Tablet, Mobile; zoom; reload; screenshot to clipboard or to the chat.
- **Comment** mode: pin a comment on an element; it is attached to the next
  turn. The Comments tab shows anchored, stale and lost comments, with images.
- **Draw** on top of the preview (pen, box, text, undo/redo).
- **Manual edit**: a layer tree and Content, Style, Attributes and HTML
  panels write the change back to the source file. Elements that hold child
  tags or are generated by scripts answer 409 with the reason.
- **Inspect**, **Tweaks** (controls the artifact declares), **palette swap**
  with 5 presets, and the **anti-slop lint** (purple gradients, emoji icons,
  default indigo…).
- **Version history** per file (AI, manual, restore) with restore.
- **Decks**: thumbnail rail, speaker notes, present in the tab, fullscreen,
  a new tab or presenter mode.
- Viewers for Markdown (Editor/Split/Preview), images, PDF, Office files,
  video, audio, live artifacts and `.jsx`/`.tsx` React components.
- **Finalize** writes a `DESIGN.md` package; **Hand off** builds a prompt
  for another editor or framework, or continues in the CLI.

```bash
od lint <project-id> [file] --fail-on p1    # exit 1 on findings at p1 or worse
```

## Files, tabs and terminal

- **File panel**: tree, breadcrumb, upload, drag and drop, paste as a file,
  folders, move, download as ZIP, copy path, delete; group by kind.
- **New sketch** and **new document** (Markdown from a template).
- **Tabs** for files, with a "+" launcher, Cmd/Ctrl+P quick switcher and
  Cmd/Ctrl+1…9.
- **Terminal tab** (`>_`): your shell (or `OD_TERMINAL_SHELL`) in the
  project folder, rendered by a bundled xterm.js. Full-screen programs such
  as `vim` and `htop` work. Switching tabs or reloading keeps the shell
  running and replays the scrollback; closing the tab stops the whole
  process tree.

```bash
od files write <project-id> index.html --content "<h1>Hi</h1>"
od files list <project-id>
```

## Export

Export (top right of the preview) or `od export <project-id> [file] --format <format>`.
Files go to the current folder by default; `--out -` writes to stdout.

| `--format` | Result | Needs |
|---|---|---|
| `html` | one self-contained HTML file (CSS, images, fonts inlined) | — |
| `zip` | the whole project (or `--root <folder>`) | — |
| `pdf` | raster PDF, one page per slide | Chrome |
| `pdf-vector` | vector PDF through the print pipeline | Chrome |
| `image` | PNG/JPEG of one slide (`--index`), the whole deck stacked, or the page | Chrome |
| `pptx` | PowerPoint, one image per slide | Chrome |
| `pptx-editable` | PowerPoint with native text boxes and shapes | Chrome |
| `mp4` | video from a HyperFrames composition | Chrome, `ffmpeg` |

The UI also exports Markdown, a React component as standalone HTML (React
and Sucrase are bundled, no CDN), and saves a project as a template.

"Chrome" means Chrome, Edge or Chromium at its standard path, or
`OD_CHROME_PATH`. Without one, those formats fail with
`this export needs Chrome, Edge or Chromium`. Contour never downloads a
browser ([decisions.md](decisions.md) §2).

## Design systems, templates, plugins and skills

- **Design systems**: 152 bundled packages plus your own. Create one from a
  brand description, a URL, a GitHub repo, a file or a pasted `DESIGN.md`;
  watch the phased generation; review (Looks good / Needs work); browse the
  kit (Showcase, Tokens, `DESIGN.md`); upload fonts and logos; set a default
  for new chats; download or edit with the agent.
- **Templates**: 115 design templates with live previews and filters, plus
  image and video prompt templates (Copy prompt) and your saved templates.
- **Plugins**: list and detail pages, Use and Remix, input forms, add from a
  prompt, a link or a folder.
- **Skills**: 169 bundled skills; create, edit or override them under the
  data folder.

```bash
od plugin list
od plugin apply <plugin-id> -i name=value     # prints the brief a run gets; exit 66 when a capability is missing
```

## Agents

Contour drives a coding agent installed on the machine; it calls a model
directly only in BYOK mode.

| Agent | Command on `PATH` |
|---|---|
| Claude Code | `claude` |
| Codex CLI | `codex` |
| Cursor Agent | `cursor-agent` |
| GitHub Copilot CLI | `copilot` |
| OpenCode | `opencode-cli`, then `opencode` |
| Qwen Code | `qwen` |

ACP agents: Kimi CLI (`kimi`), Hermes (`hermes`), Kiro CLI (`kiro-cli`),
Kilo (`kilo`), Mistral Vibe (`vibe-acp`), Trae CLI (`traecli`), DeepSeek
Reasonix (`reasonix`), Devin for Terminal (`devin`), DeepSeek Harness
(`dsh`, then `dsnix`). More CLIs (Aider, Amp, Qoder and others) are listed
in [parity.md](parity.md) row 174.

**Detection** runs each time the agent picker opens or `GET /api/agents` is
called: the daemon finds the binary on its `PATH`, runs `--version` and reads
`--help` for supported flags (5 seconds per command). Nothing is cached, so
after installing an agent press **Refresh**.

```bash
curl -s http://127.0.0.1:7456/api/agents
```

The agent runs with the project folder as its working directory. The daemon
removes inherited `OD_*` variables (including `OD_API_TOKEN`) and sets the
run's own: `OD_PROJECT_DIR`, `OD_DAEMON_URL`, `OD_TOOL_TOKEN`, `OD_BIN`…

### Permissions

The default is **Automatic**, as in the original app: Claude runs with
`--permission-mode bypassPermissions` and other agents get their
self-approve flag. **Ask first** (Settings ▸ Permissions) gives Claude
`acceptEdits` only and drops the flag for the others. An agent waiting for an
approval nobody gives hangs until its timeout.

```bash
curl -s -X PUT http://127.0.0.1:7456/api/app-config \
  -H 'content-type: application/json' -d '{"agentPermissionMode":"ask"}'
```

### BYOK (API key)

Without an agent CLI, pick **API key (BYOK)**: the daemon calls the Anthropic
Messages API, an OpenAI-compatible `chat/completions` endpoint, or Azure
OpenAI, from 26 presets. The model has no tools and returns one HTML file.

```bash
curl -s -X PUT http://127.0.0.1:7456/api/app-config \
  -H 'content-type: application/json' \
  -d '{"byok":{"protocol":"anthropic","apiKey":"sk-ant-...","model":"claude-opus-5-5"}}'
```

- `protocol`: `anthropic`, `openai` (or `openai-compatible`), `azure`.
- Optional `baseUrl` for self-hosted endpoints and `maxTokens`.
- The key is stored in `<data folder>/app-config.json` (mode `0600`). The API
  never returns it and it is sent only to the configured endpoint.

## Settings

Settings (Cmd/Ctrl+,): agent and model (reasoning effort, service tier),
connection test, proxy and custom paths, BYOK, permissions, language (20),
theme, notifications (sound, desktop), project locations, global rules,
global memory (hooks, import, `MEMORY.md`), media providers, and About
(version, diagnostics export, reset onboarding).

## Media

Image, video and audio projects use your own keys for OpenAI Images, fal.ai,
ElevenLabs and the other providers in Settings ▸ Media (or
`OD_OPENAI_API_KEY`, `OD_FAL_KEY`, `OD_ELEVENLABS_API_KEY`). The chat shows
a progress row per task and an audio player. The **Library** collects every
generated or uploaded asset; *Chat to design* starts a project from one.

```bash
od media generate --help
```

## Automations

**Automations** runs a prompt in a project on a local cron schedule, or on
**Run now**. Each run is a normal agent run in a new conversation named
after the routine, so it can be reviewed in the Studio.

- Schedules: 5-field cron (`minute hour day month weekday`, with `*`, lists,
  ranges, steps) or `@hourly`, `@daily`, `@weekly`, `@monthly`.
- A routine never overlaps itself: a run due while the previous one is still
  going is recorded as `skipped`.
- Missed runs are not caught up while the daemon is off.
- **Crystallize** turns a good run into a routine; evolution proposals
  suggest changes you can apply. Live artifacts can be refreshed on demand.
- API: `GET/POST /api/routines`, `POST /api/routines/:rid/run`,
  `GET /api/routines/:rid/runs`.

## MCP

**Contour as an MCP server** for your coding agent (Claude Code, Codex,
Cursor): the agent reads and edits projects, runs lint and export through
the running daemon.

```bash
od mcp install claude --print      # show the command or config it would write
od mcp install claude              # register the "open-design" server in Claude Code
od mcp install cursor              # write ~/.cursor/mcp.json, keeping other servers
od mcp install claude --uninstall
```

`od mcp` with no arguments is that stdio server; `od mcp live-artifacts` is a
second server for live artifacts.

**Contour as an MCP client**: Settings ▸ MCP servers declares your stdio or
HTTP servers (env, headers, OAuth 2.1 when the server asks). The daemon tests
the connection, lists tools, and writes the enabled servers into the config
of each agent it spawns. Only Claude, ACP agents and OpenCode receive them,
as in the original app; ACP takes stdio servers only. Secrets live in `0600`
files under the data folder and the API returns them masked.

## Desktop app

- The daemon runs inside the app on a fresh loopback port each launch; no
  sidecar process.
- It shares the data folder with `od`. If an `od` daemon already owns it,
  the app says so and quits; stop `od` first.
- **Project ▸ Open Folder…** (Cmd+O), **Help** ▸ Documentation, Report Issue
  (copies a diagnostics summary and opens the run log folder), Show Data
  Folder, Keyboard Shortcuts, Command Palette.
- Started from Finder or the Dock, the app takes `PATH` from your login
  shell (plus `~/.local/bin`, Homebrew, npm, bun, cargo) to find agents.
- Quitting stops every terminal shell and running agent.
- The window follows the system theme and opens on a splash screen while
  the daemon starts.

## CLI reference

Every command except `od` / `od daemon start` is a thin client of the HTTP
API. `--json` prints JSON, `--daemon-url` (or `OD_DAEMON_URL`) picks the
daemon, `od <command> --help` lists the options.

| Command | Does |
|---|---|
| `od`, `od daemon start [--port N]` | run the daemon |
| `od daemon status` | check a daemon is answering |
| `od project create\|list` | projects |
| `od files write\|list` | project files |
| `od run start\|watch\|cancel\|list` | agent runs |
| `od lint` | anti-slop lint, exit 1 on findings at `--fail-on` or worse |
| `od export` | export, see [Export](#export) |
| `od media generate\|wait\|cancel` | media tasks |
| `od plugin list\|info\|apply\|validate` | plugins |
| `od mcp`, `od mcp install` | MCP server and installer |

## Environment variables

| Variable | Meaning | Default |
|---|---|---|
| `OD_DATA_DIR` | data folder (SQLite, projects, runs) | see [getting-started.md](getting-started.md#where-your-work-lives) |
| `OD_PORT`, `OD_HOST` | daemon address | `7456`, `127.0.0.1` |
| `OD_API_TOKEN` | token required when binding beyond loopback | — |
| `OD_ALLOWED_ORIGINS` | extra origins allowed to call the API, comma-separated | the daemon's own |
| `OD_DAEMON_URL` | daemon the client commands call | `http://127.0.0.1:7456` |
| `OD_RESOURCE_ROOT` | the `content/` folder (skills, templates, design systems) | next to the binary, then the source tree |
| `OD_UI_DIST` | built UI folder | `ui/` next to the binary, then `crates/od-ui/dist` |
| `OD_CHROME_PATH` | Chrome/Edge/Chromium for export | found automatically |
| `OD_CHROME_NO_SANDBOX` | `1` starts Chrome without its own sandbox; only when Contour itself already runs inside one (`sandbox-exec`, some containers) | off |
| `OD_FFMPEG_PATH` | `ffmpeg` for MP4 | `PATH`, Homebrew |
| `OD_TERMINAL_SHELL` | shell of terminal tabs | `$SHELL` |
| `OD_MEDIA_CONCURRENCY` | media tasks in parallel | `2` |
| `OD_OPENAI_API_KEY`, `OD_FAL_KEY`, `OD_ELEVENLABS_API_KEY` | media keys (or `media-config.json`) | — |
| `OD_CRITIQUE_ENABLED` | Design Jury on by default | off |
| `OD_WATCHER_USE_POLLING` | poll for file changes (network drives, Docker) | off |
| `OD_OPEN_COMMAND` | command that opens folders and links instead of Finder or `xdg-open` | per OS |
| `RUST_LOG` | log filter for the daemon and the app ([development.md](development.md#logs)) | `info` |

## Not in Contour

Some parts of OpenDesign are deliberately left out because they need an
account, a cloud service or outbound network ([decisions.md](decisions.md)):
connectors (Composio), Orbit digests, Figma import, marketplace and registry,
the floating pet, the built-in browser tab, Web Clipper, xAI OAuth, team
spaces and sharing, deploy to Vercel/Cloudflare, cloud sign-in and
auto-update. [parity.md](parity.md) marks them N/A.
